# Field anatomy

The parts a form field is built from, and what each one must do. They are built by `OField`,
`OInput` (in an `OControlFrame`), `OFieldset` and `OForm`. Switch **Theme**, **Mode** and
**Language** in the toolbar: the diagram uses the same tokens as the components.

| #   | Part                         | Element                                       | Rules                                                                                                                                                                                              |
| --- | ---------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Label**                    | `<label for>`                                 | Always visible. A placeholder never replaces it.                                                                                                                                                   |
| 2   | **Required/optional marker** | text inside the label                         | `*` for required, `(optional)` for optional, or both (see below). The text follows the form's language. The control still gets `required`, so screen readers announce it.                          |
| 3   | **Label action**             | `#label-action` slot                          | An optional link or toggletip ("Forgot password?"). It is its own focusable element, before the control in tab order.                                                                              |
| 4   | **Hint**                     | `<p id>`                                      | **Above** the control, so it's read before typing and the on-screen keyboard or autofill can't cover it. Linked with `aria-describedby`.                                                           |
| 5   | **Control frame**            | `OControlFrame`                               | Draws the border, background, radius and focus ring (when the native control has visible focus), so adornments sit inside the box. `OInput` uses it; so can your own controls.                     |
| 6   | **Leading adornment**        | `icon` / `prefix` props, `#leading` slot      | A decorative icon (`aria-hidden`), or prefix text such as `€` or `https://`. Prefix text carries meaning, so it is linked to the control with `aria-describedby`.                                  |
| 7   | **Native control**           | `<input>`, `<textarea>`, `<select>`           | Gets `id`, `required`, `disabled` / `readonly`, `aria-invalid` and `aria-describedby`.                                                                                                             |
| 8   | **Trailing adornment**       | `suffix`, `clearable` props, `#trailing` slot | Suffix text, a status icon (error, or `OSpinner` while loading), and actions (clear, show password). Actions are real `<button>`s with a translated `aria-label` and a target of at least 24×24px. |
| 9   | **Error message**            | `<p id>`                                      | Shown **as well as** the hint, below the control. An icon labelled "Error:" plus text, so color is not the only signal. Linked with `aria-describedby` after the hint.                             |
| 10  | **Counter**                  | `maxLength` prop                              | Optional. A polite live region that only speaks near the limit ("5 characters left"), not on every keystroke.                                                                                      |

The control's `aria-describedby` lists, in order: the prefix/suffix text, the hint, the error and
the counter. The field decides _what_ the error says; _when_ it appears is up to the form (on
blur, on submit, …).

## Layout

Fields are **stacked**: label, hint, control and message, top to bottom. There is no
label-beside-control variant. The gaps come from theme tokens (`--oct-field-gap`), so a
dense theme (Circuit) and a roomy one (Vellum) space fields differently.

## Groups: `OFieldset`

Radio buttons, checkboxes and inputs split into parts (day / month / year) share one label. They
use a `<fieldset>` with a `<legend>` instead of a `<label>`, and have the same marker, hint, error
and layout as a field. Controls inside pick up `invalid` and `disabled` from the group. A required
group says "required" to screen readers in its legend, because a group has no `required` attribute.

```
┌ fieldset ───────────────────────────┐
│ legend   Delivery  (optional)       │
│ hint     Pick one.                  │
│ controls ○ Standard  ○ Express      │
│ error    ⚠ Choose a delivery option.│
└─────────────────────────────────────┘
```

## Required and optional markers

`<OForm markers="…">` chooses how its fields are marked (default `required`), and a field or group
can override it with its own `markers`. The note only appears when a field shows a `*`.

| Mode       | Required field | Optional field       | Note at the top of the form      |
| ---------- | -------------- | -------------------- | -------------------------------- |
| `required` | `Name *`       | `Website`            | "Fields marked \* are required." |
| `optional` | `Name`         | `Website (optional)` | none                             |
| `both`     | `Name *`       | `Website (optional)` | "Fields marked \* are required." |

- The `*` is hidden from screen readers (`aria-hidden`); `required` on the control announces it.
- `(optional)` is visible text inside the `<label>`, so it is part of the accessible name, and
  speech-input users can say it (WCAG 2.5.3).

## Language

Text that Octarine writes itself must follow the language of the form, not just of the app:
`(optional)`, the required note, the counter, the "Error:" label and the names of actions like
_Clear_ or _Show password_.

- **Which language:** the `lang` of the enclosing `OForm`, so `<OForm lang="fr">` inside an English
  page gets French. Without one, `<html lang>`, which every app must set anyway (WCAG 3.1.1).
  Octarine follows changes to `<html lang>` while the app runs.
- **Where the text comes from:** `@octarine/i18n` has a file per language: English (built in),
  Dutch, French and German. Apps import the ones they use and add languages or change words the
  same way: `app.use(createMessages({ nl, es: { 'field.optional': '(opcional)', … } }))`. A
  regional tag (`nl-BE`) uses its own entries, then the language's, then English; a language
  with no file falls back to English with a console warning.
- Text the app passes in (label, hint, error) is the app's job to translate.
